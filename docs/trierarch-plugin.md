# The trierarch plugin: architecture

`@aeolus-fleet/trierarch-plugin`: a long-running Node process, hosted beside squadrons, serving every fleet of the server with one connection each and switched per fleet as squadrons is (decisions [0021](https://github.com/ThomasHendrickx/aeolus-fleet/blob/main/docs/decisions/0021-squadrons-installation.md), [0030](decisions/0030-trierarch-plugin.md)). It reaches each fleet only through the public API, as that fleet's trierarch plugin ship (`fleet:read`, `fleet:commission`, `crew:assign`, `crew:run`, `labels:define`, `labels:assign` and `scopes:declare`). It follows the fleet's changes, and every check-in returns the latest full state. Its own small database holds per fleet only the connection (its ship and kept crew token) and the switch, set through installation procedures as squadrons' are; it may share squadrons' Postgres server, in its own schema. Everything else (requests, statuses, machines) lives in the fleet. It depends on `common` only.

What lives in core: the product and its language in aeolus-fleet's [blueprint](https://github.com/ThomasHendrickx/aeolus-fleet/blob/main/docs/blueprint.md), what the trierarch plugin and the trierarchs do in [docs/trierarch.md](https://github.com/ThomasHendrickx/aeolus-fleet-trierarch/blob/main/docs/trierarch.md), the crew request in decision [0029](https://github.com/ThomasHendrickx/aeolus-fleet/blob/main/docs/decisions/0029-crew-request.md), and the calls this package makes and the minimum core version it checks in [docs/compatibility.md](https://github.com/ThomasHendrickx/aeolus-fleet/blob/main/docs/compatibility.md).

| Layer | Pieces |
| --- | --- |
| Core (pure) | **Placement**: a pure function from (the unassigned requests, oldest first, the trierarchs' reports, the requests assigned to each) to the trierarch to claim for each, or the reason none fits; the only place that picks. It keeps the trierarchs that fit (repository, harness, model) and have room, then takes the most room as a percentage, then the oldest. **Assignment pass**: per fleet, read the unassigned requests and the trierarchs, place, then claim or write the reason; a lost claim is read again on the next pass. **Join**: refuse an actor without `trierarch:join` (argo always may), then commission a trierarch ship with `crew:run` and answer its starting prompt and the machine's setup line. **Machines**: the fleet's ships of type `trierarch`, each with its trierarch's report and details, whether it is silent, and their labels. **Network**: declare `trierarch=*` to `trierarch=*`, withdrawn when off or deleted. **Scopes**: declare the namespace `trierarch` with `trierarch:join` while its ship does not hold it; tell argo once while another ship does. **Connection**, **installation** and **operator** |
| Ports | **FleetDoor**: the ship calls it makes as its ship. **ConnectionStore**, **FleetSwitches**, **InstallationRequests**, **FleetForgetter**, **ConsoleSessions**, **IdempotencyKeys**, **RequestHasher**, **Clock** |
| Adapters | REST to the fleet; tRPC for the web app's server (`connection`, `machines`, `requests`, `installation`), checked with the console session cookie through `console.session`; Prisma on its own database (`connections`, `fleet_switches`, `installation_requests`); an assignment pass on a timer for every fleet it serves and is connected to |

## Deployment

A long-running Node process beside squadrons, with a small Postgres database of its own holding each fleet's connection and switch (it may share squadrons' Postgres server, in its own schema), on any VM or container host next to the server. It needs no public address: only the web app's server and the fleet's API talk to it or it to them.
